# 開発工程の全体像

ソフトウェア開発は、いくつかの工程を経て進められます。まずは全体像を把握しましょう。

## 開発工程とは

ソフトウェア開発は、「作りたいものを決める」から「実際に使えるようにする」まで、段階的に進めます。各工程には役割があり、順番に進めることで品質を保ちます。

## 基本的な開発工程

### 1. 要件定義

**何を作るかを決める工程**

- お客様の要望を聞き取る
- システムで実現したいことを明確にする
- 「何を作るか」を文書にまとめる

### 2. 設計

**どう作るかを決める工程**

- **基本設計（外部設計）**：画面や機能の設計
- **詳細設計（内部設計）**：プログラムの処理内容の設計

設計書を作成し、実装の指針とします。

### 3. 実装（コーディング）

**実際にプログラムを書く工程**

- 設計書に基づいてコードを書く
- コーディング規約に従う
- コードレビューを受ける

### 4. テスト

**作ったものが正しく動くか確認する工程**

| テストの種類 | 内容 |
|-------------|------|
| 単体テスト | 個々の機能が正しく動くか確認 |
| 結合テスト | 複数の機能を組み合わせて確認 |
| システムテスト | システム全体が要件を満たすか確認 |
| 受け入れテスト | お客様に確認してもらう |

### 5. リリース・運用

**システムを本番環境で稼働させる工程**

- 本番環境への導入
- 運用開始後の監視
- 問題発生時の対応

### 6. 保守

**運用中のシステムを維持・改善する工程**

- バグの修正
- 機能の追加・改善
- パフォーマンスの改善

## 開発手法

### ウォーターフォール型

各工程を順番に進める手法。

```
要件定義 → 設計 → 実装 → テスト → リリース
```

**特徴**
- 工程が明確で管理しやすい
- ドキュメントがしっかり作られる
- 途中での仕様変更が難しい

**よく使われる現場**
- 大規模な業務システム
- 品質要件が厳しいシステム

### アジャイル型

短いサイクルで開発を繰り返す手法。

```
計画 → 開発 → テスト → レビュー → 計画 → ...（繰り返し）
```

**特徴**
- 変化に柔軟に対応できる
- 短期間で動くものができる
- コミュニケーションが重要

**よく使われる現場**
- Webサービス
- スタートアップ

## 1年目エンジニアの関わり方

1年目は主に以下の工程に関わることが多いです。

| 工程 | 1年目の関わり方 |
|------|----------------|
| 設計 | 設計書を読んで理解する |
| 実装 | 設計書に基づいてコードを書く |
| テスト | テスト仕様書に基づいてテストを実行する |
| 保守 | 既存システムのバグ修正を担当する |

## まとめ

- 開発工程は「何を作るか」→「どう作るか」→「作る」→「確認する」→「使う」の流れ
- 現場によってウォーターフォール型かアジャイル型かが異なる
- 1年目は主に実装・テストに関わることが多い
