# コードを読む・書く基礎

コードを読むスキルと書くスキルの基礎を学びます。

## コードを読む

### なぜコードを読むスキルが重要か

- 既存のコードを理解して修正・拡張する
- 他の人のコードから学ぶ
- コードレビューで指摘を理解する

1年目は「書く」より「読む」時間の方が長いことも多いです。

### コードを読むコツ

#### 1. 全体構造を把握する

いきなり細かいコードを読まず、まず全体を把握します。

- フォルダ構成を確認
- ファイル名から役割を推測
- クラスやメソッドの名前を見る

#### 2. 処理の流れを追う

- エントリーポイント（処理の開始点）を見つける
- 上から下へ、呼び出し順に追う
- デバッガを使って実際に動かしながら確認

#### 3. 分からないところはメモする

- 後で調べる・質問するためにメモ
- 「何が分からないか」を明確にする

### 読むときの注意点

- 一度に全部理解しようとしない
- 自分の担当範囲から読み始める
- コメントやドキュメントも参考にする

## コードを書く

### コーディング規約

コーディング規約とは、コードを書く際のルールやスタイルです。

**なぜ必要か**
- チーム内でコードの書き方を統一する
- 読みやすく保守しやすいコードにする
- 将来の自分や他のエンジニアが理解しやすくする

現場ごとに規約があるので、まず確認しましょう。

### 命名規則

意味のある名前をつけることが重要です。

**良い例**
```java
int totalAmount;           // 合計金額
String userName;           // ユーザー名
void calculateTax() {}     // 税金を計算する
```

**悪い例**
```java
int a;                     // 何の値か分からない
String str1;               // 何の文字列か分からない
void func() {}             // 何をする関数か分からない
```

**命名スタイル**

| スタイル | 例 | 用途 |
|---------|-----|------|
| camelCase | userName | 変数名、メソッド名 |
| PascalCase | UserName | クラス名 |
| snake_case | user_name | 変数名（言語による） |
| UPPER_SNAKE_CASE | MAX_VALUE | 定数 |

### コードのフォーマット

#### インデント
- スペース4つ、またはタブ1つ（チームのルールに従う）
- インデントを揃えることで構造が見やすくなる

#### 空白と改行
```java
// 読みやすい
int total = price * quantity + tax;

// 読みにくい
int total=price*quantity+tax;
```

#### 1行の長さ
- 長すぎる行は適切に改行する
- 目安は80〜120文字程度

### コメントの書き方

#### 良いコメント

**「なぜ」を書く**
```java
// 税率は法改正で変更される可能性があるため、定数として定義
final double TAX_RATE = 0.10;
```

**複雑な処理の意図を説明する**
```java
// 配列を逆順にソートすることで、最新のデータが先頭に来るようにする
Arrays.sort(data, Collections.reverseOrder());
```

#### 悪いコメント

**コードを日本語に訳しただけ**
```java
// iに1を加える
i = i + 1;
```

**古くなって嘘になっている**
```java
// 税率8%で計算（実際は10%に変更済み）
double tax = amount * 0.10;
```

### コードレビューを受ける心構え

- 指摘は「コード」に対するもので、「人格」への攻撃ではない
- 分からない指摘は質問する
- 学びの機会として捉える
- 同じ指摘を繰り返し受けないようにメモする

## まとめ

**読むスキル**
- 全体構造から把握する
- 処理の流れを追う
- 分からないところはメモして後で確認

**書くスキル**
- 現場のコーディング規約に従う
- 意味のある名前をつける
- 「なぜ」を説明するコメントを書く
- コードレビューを学びの機会にする
